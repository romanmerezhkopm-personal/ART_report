# Weekly ART Report — Контекст проекта

## Что это

Еженедельный HTML-отчёт по затраченному времени ART-отдела PSV Studio.
Данные берутся из Asana через Personal Access Token (PAT).

---

## Файлы в этой папке

| Файл | Назначение |
|---|---|
| `asana_pat.txt` | Personal Access Token Asana (одна строка) |
| `run_art_report.ps1` | Генератор отчёта (единственный актуальный скрипт) — `& run_art_report.ps1 -Start yyyy-MM-dd -End yyyy-MM-dd [-Label "..."]` |
| `ART_report_YYYY-MM.html` | Готовые отчёты по месяцам |
| `may_time_data.json` | Кэш time_tracking_entries за май 2026 (129 задач) |
| `CONTEXT.md` | Этот файл |

---

## Как генерировать отчёт

1. Прочитать PAT из `asana_pat.txt`
2. Для каждого из 10 ART-проектов получить задачи: `GET /projects/{gid}/tasks?opt_fields=gid,name,memberships,memberships.project.gid,memberships.project.name`
3. Для фильтрации по периоду использовать PowerShell + PAT:
   ```powershell
   $headers = @{ Authorization = "Bearer <PAT>" }
   Invoke-RestMethod "https://app.asana.com/api/1.0/tasks/<GID>/time_tracking_entries?opt_fields=duration_minutes,entered_on" -Headers $headers
   ```
   Фильтровать по `entered_on` в нужном диапазоне дат.
4. Применить логику атрибуции (см. ниже)
5. Записать HTML: `ART_report_YYYY-MM.html`

**Класс проблемы:** `GET /portfolios/{gid}/items` возвращает и проекты, и под-портфели
(`resource_type = portfolio`). Плоский фильтр `resource_type -eq "project"` молча теряет всё, что
лежит внутри под-портфеля — без ошибки, отчёт просто выходит неполным. Старый fetch в
`run_art_report.ps1` видел бы 8 из 18 проектов.

рекурсивно (защита от циклов, пагинация по `next_page.offset`). Правило стоит прямо у точки решения:
- неизвестный `resource_type` → `throw` (не пропуск);
- сбой чтения под-портфеля → `throw` (не откат на устаревший список из 13; хардкод-fallback
  остаётся только для пустого результата без ошибки).

Что блокируется: элемент неизвестного типа; ошибка API на вложенном портфеле.
Что пропускается: заархивированные проекты, повторно достижимый портфель (цикл/дубль).

## Логика атрибуции задач

Задачи в Asana могут быть одновременно в нескольких проектах (multi-home).

**Правило:** учётный проект = первый проект задачи, который **НЕ входит** в ART-портфель.

**Примеры:**
- Задача в `2D Art Backlog` + `Brain Puzzle` → учитывается как **Brain Puzzle**
- Задача только в `ASO Icons` → **ASO Icons**
- Задача только в `3D Art Backlog` без внешнего проекта → смотреть имя задачи и родительскую задачу

**Особые случаи (выявлены в мае 2026):**

| Ситуация | Атрибуция |
|---|---|
| Подзадачи Level 1–6 в 2D Art Backlog | → **Brain Puzzle** (родитель: "Новые уровни брейнов (6 штук)") |
| Подзадачи Level 16–24 в 2D Art Backlog | → **Brain Puzzle** (родитель: "Подготовить для переноса уровни сторисов в брейн") |
| 3D Art Backlog задачи с родителем "Обновление Ночной карты" | → **Custom Club** |
| 3D Art Backlog задачи с `< DriveCSX >:` в имени | → **DriveCSX** |

## Формат отчёта (обязательный)

HTML-файл со следующими секциями:

1. **Header** — фиолетовый градиент `#667eea → #764ba2`, 4 stat-карточки: Часов / Задач / Проектов / Направлений ART
2. **Notice** — зелёный (time_tracking_entries, точный период) или жёлтый (накопленное время)
3. **Разбивка по направлениям ART** — dept-grid карточки
4. **Сводная таблица по проектам** (`id="summary"`) — **объединённая секция** (правка 14.08.2026, решение
   Романа: слить бывшие отдельные «Распределение по проектам» / «Сводная таблица» / «Детализация задач»
   в одну). Каждый проект — раскрывающаяся строка `<details class="proj-row">`:
   - в свёрнутом виде: ранг-бейдж, название проекта, пилюли направлений ART, кол-во задач, **цветной
     прогресс-бар с % внутри** (ширина = доля часов проекта от максимума среди проектов, цвет —
     по индексу из палитры `$barColors`, ровно то же вычисление, что раньше было в отдельной
     диаграмме-распределении)
   - по клику разворачивается таблица задач: Задача / Направление / Исполнитель / Часов
   - в конце секции — строка ИТОГО (кол-во проектов, задач, часов, 100%)
   Старых отдельных якорей `#distribution` и `#project-details` в отчёте больше нет — все ссылки на
   них нужно менять на `#summary`.
5. **Footer** — дата генерации, источник, период

**Никаких минут** — только часы везде.

Эталонные файлы: `ART_report_2026-05.html`, `ART_report_2026-06.html` — ⚠️ **устарели по структуре**
(старый 3-секционный формат до правки 14.08.2026, не перегенерировались). Актуальный эталон —
`ART_report_2026-07.html` (пересобран 14.08.2026 с новым форматом и фиксом ниже).

### Фикс: лимит Asana Search API в 100 результатов (14.08.2026)

Step 2.5 («Art Team members + их задачи вне ART-портфеля», см. `run_art_report.ps1`) искал задачи
через `tasks/search?assignee.any=...&modified_on.after=...` — этот endpoint **не отдаёт больше 100
результатов и не паджинирует** (без ошибки, без `next_page` — просто молча обрезает). При большом
объёме задач у одного сотрудника это занижало охват. Исправлено функцией `Get-CandidateTasksAdaptive`:
диапазон дат рекурсивно делится пополам при получении ровно 100 результатов, подзапросы мержатся,
пока каждый не уложится в лимит (либо не упрётся в один день — тогда принимается как есть, с
`WARNING` в лог). На цифры разделов «Распределение/Сводная таблица» это почти не повлияло (Step 2.5
там не участвует — только в разделе «По сотрудникам»), но исправлено ради полноты и корректности
общей статистики.
